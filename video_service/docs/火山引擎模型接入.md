# 火山引擎模型接入（视频 MVP）

状态：代码已接入，单元测试通过；录音文件接口已于 2026-09-17 用 16.44 秒美妆视频音轨完成一次真实联调。模型 ID 与后续接口字段仍以火山控制台和当前官方文档为准。

## 1. 模型选择

| 环节 | 服务 | 默认模型 | 说明 |
| --- | --- | --- | --- |
| 画面 OCR | 本地 RapidOCR/ONNXRuntime（PP-OCR） | `rapidocr-onnxruntime>=1.4,<2` | 高覆盖文字抽取，全量采样帧本地运行；不上传画面做 OCR |
| 画面视觉 | 火山方舟 Ark（OpenAI 兼容 `/chat/completions`） | `doubao-seed-2-1-pro-260915`（豆包 Seed 2.1 Pro 稳定版） | 多模态理解 + 结构化 JSON 输出；适合最多 12 帧的证据级观察。`doubao-seed-evolving` 更强但周级变化，不适合默认法务留痕 |
| 口播识别 | 豆包录音文件识别大模型版（openspeech.bytedance.com，提交-轮询） | resource_id `volc.seedasr.auc`，`model_name=bigmodel` | 已实测 `x-api-key` + base64 `audio.data` 可用；设为云端主识别后，仍保留本地 SenseVoice 独立交叉校验 |

型号 ID 以方舟“模型列表”和控制台推理接入点为准，写入 `.env.video.volc.example` 即可，无需改代码。当前启动脚本默认读取该文件；它已经加入 `.gitignore`，名称虽含 example，但作为本机私有运行配置使用。

## 模型选型说明

本任务不是开放式聊天，而是让模型按固定 JSON schema 观察画面中的商品、动作、场景、背书和促销呈现。默认选择 Seed 2.1 Pro 稳定版，而不是 `doubao-seed-evolving`：前者便于跨天复现审核结果，后者适合追求最新能力的探索性测试。当前不需要 `doubao-embedding-vision`；图文向量模型只用于相似度检索，例如后续建设“客户自有 IP/logo 以图搜图”库。规则匹配、OCR 文本审核和当前画面语义观察均不依赖图片向量化。

## 2. 配置

直接编辑 `.env.video.volc.example`（已 gitignore）。如要显式指定其他文件，可设置 `VIDEO_MVP_ENV_FILE`。

填入：

- `VIDEO_MVP_CLOUD_API_KEY`：方舟 API Key；
- `VIDEO_MVP_VOLC_SPEECH_API_KEY`：语音服务 API Key，对应请求头 `x-api-key`；它不是 IAM AccessKey ID/Secret；
- 如控制台分配的 resource_id 不同，改 `VIDEO_MVP_VOLC_SPEECH_RESOURCE_ID`，当前官方示例为 `volc.seedasr.auc`。

启动：

```bash
VIDEO_MVP_PORT=8511 make video-mvp
# 健康检查中应出现 asr.volc.configured=true、visual_config.endpoint=ark.cn-beijing.volces.com
curl -s http://127.0.0.1:8511/health
```

不设 `VIDEO_MVP_ASR_ENGINE=volc` 时仍走本地双引擎，互不影响。

## 3. 数据外发边界（强制）

- 视觉：每次任务仍需在上传页**逐次勾选目的地授权**；目的地从交大地址变为 `ark.cn-beijing.volces.com` 后，旧授权全部失效，需重新确认。只发代表帧（≤12 张）和对应机器口播片段，不发完整视频、材料、活动规则、落地页。
- 语音：已实测可发送单音轨转码后的 16 kHz 单声道 WAV（base64 `audio.data`，约 0.5 MB/16 秒）；必须显式设置 `VIDEO_MVP_VOLC_SPEECH_INLINE_DATA=1`。上传内容**不含视频画面与任何材料**。
- 凭据只允许存在已 gitignore 的本机配置文件，代码与日志不落密钥；异常只记录异常类型和协议码。

## 4. 待实机验证的协议假设

以下按官方公开文档实现，但本次环境无法联网核实，联调时需逐项确认：

1. 官方提交路径 `/api/v3/auc/bigmodel/submit` 已按示例校正；查询路径按同前缀 `/query` 实现；
2. 请求头按官方示例使用 `x-api-key`、`X-Api-Resource-Id`、`X-Api-Request-Id`、`X-Api-Sequence: -1`；
3. 成功码 `1000`、识别中 `1001` 仍需实机确认；
4. `audio.data` 已在 2026-09-17 实测可用；如火山后续调整协议，可回退到 TOS 临时 `audio.url`；
5. `request.hotwords` 平台热词字段不在官方示例中，默认关闭；如不支持，保持 `VIDEO_MVP_VOLC_HOTWORDS=0` 或改为控制台热词表方案；
6. utterance 时间字段 `start_time/end_time` 为毫秒、词级 `words` 返回结构。

实测结论：submit 成功返回 HTTP 200 空 JSON；query 使用空 JSON body，成功结果位于 `result.result`，含句级 `utterances` 与毫秒时间戳；HTTP 200 空壳表示仍在处理，需要继续轮询。

## 2026-09-17 补充：移植入新取证层 backend

同一协议已移植到取证层 Provider 抽象：`backend/app/pipeline/providers/volcengine.py`
（`VolcSeedASR`，`ASR_PROVIDER=volcengine` + `ASR_VOLC_API_KEY` 启用，兼容旧 `VIDEO_MVP_VOLC_SPEECH_*` 变量名）。

硬指标落地方式：除基类能力闸门外，**每次响应强制复验** utterance/words 字级时间戳——
缺 words、覆盖率不足、时间回退一律抛 `WordTimestampMissing`，不静默降级到段级。

字级时间戳验收脚本（§11 指标 ≤0.5s）：

```bash
# 结构验收：留存产物是否真带字级时间戳（已对 2026-09-17 联调留存样本验证 PASS）
PYTHONPATH=backend .venv-handoff/bin/python \
  backend/scripts/verify_asr_word_timestamps.py verify data/video_mvp/jobs/<id>/asr_raw.json

# 误差验收：需人工逐词核对的标签（每供应商/每素材类型 ≥10 词）
PYTHONPATH=backend .venv-handoff/bin/python \
  backend/scripts/verify_asr_word_timestamps.py measure \
  data/video_mvp/jobs/<id>/asr_raw.json \
  --labels datasets/golden/asr_timestamp_labels/<name>.yaml
```

注意：2026-09-17 同一条 16.44s 美妆音轨两次调用，一次成功（job `3e669488…`，3 段全带字级）、
一次返回 `no_speech_detected`（job `5d663942…`）。空结果占比需在金标准集上量化，
若复现率高要回到供应商侧排查（疑似 inline data 参数或音频规格问题），不能当成偶发。
