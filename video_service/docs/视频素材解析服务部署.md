# 视频素材解析服务部署（生产目标）

## 1. 职责边界

该服务只把视频转换为可追溯证据：接收视频、抽帧、ASR、OCR、视觉语义观察、候选特征与时间戳/帧号/bbox/置信度留痕。服务不输出“违法/合规/通过”最终结论；最终规则召回、RAG、风险等级和法律推理由 rule_engine 完成。

正式端口固定为 **8520**，默认仅监听 `127.0.0.1`，由 Nginx 加 HTTPS、鉴权和访问控制后对外提供。

## 2. 接口

- `GET /health`：进程存活，不要求外部依赖全部可用。
- `GET /ready`：ffmpeg/ffprobe、ASR/OCR/VLM、数据目录、SQLite、磁盘空间、rule_engine URL 配置；依赖不满足返回 503。
- `POST /api/video/jobs`：multipart 上传视频，头 `X-API-Key`，表单可传 `record_id`、`material_id`、`dedupe_by_hash`。
- `GET /api/video/jobs/{job_id}`：查询状态。
- `GET /api/video/jobs/{job_id}/evidence`：统一证据协议。
- `GET /api/video/jobs/{job_id}/result`：证据 + rule_engine 返回。

状态：`queued / processing / completed / partial / failed`。rule_engine 不可用时为 `partial`，不是通过。

## 3. 规则引擎调用

环境变量：

- `RULE_ENGINE_URL`，例如 `http://127.0.0.1:8505`
- `RULE_ENGINE_API_KEY`
- `RULE_ENGINE_CONNECT_TIMEOUT=5`
- `RULE_ENGINE_READ_TIMEOUT=30`
- `RULE_ENGINE_RETRIES=2`

视频服务把 evidence 转成当前 rule_engine `/audit` 的文本协议，并发送 `X-Request-ID` 与 `Idempotency-Key`。后续若 rule_engine 提供原生 evidence endpoint，只需替换 `src/video_service/rule_engine.py`。

## 4. 从零部署（Ubuntu 22.04）

```bash
sudo useradd --system --home /opt/adsure-video-review --shell /usr/sbin/nologin adsure
sudo mkdir -p /opt/adsure-video-review /var/lib/adsure-video /etc/adsure
sudo chown -R adsure:adsure /opt/adsure-video-review /var/lib/adsure-video /etc/adsure
sudo apt-get update
sudo apt-get install -y python3.11 python3.11-venv ffmpeg git
sudo -u adsure git clone <repo> /opt/adsure-video-review
cd /opt/adsure-video-review
sudo -u adsure python3.11 -m venv .venv-video
sudo -u adsure .venv-video/bin/pip install -r requirements-video.txt
# 下载/初始化本地模型（模型目录按现有 setup_models 文档执行）
sudo cp deploy/video.env.example /etc/adsure/video.env
sudo cp deploy/systemd/adsure-video.service /etc/systemd/system/adsure-video.service
sudo systemctl daemon-reload
sudo systemctl enable --now adsure-video
```

预检：

```bash
sudo -u adsure VIDEO_SERVICE_API_KEY=change-me .venv-video/bin/python -m scripts.preflight_video
```

冒烟：

```bash
VIDEO_SERVICE_URL=http://127.0.0.1:8520 VIDEO_SERVICE_API_KEY=change-me \
  .venv-video/bin/python scripts/smoke_video_service.py
```

真实小视频素材可用 `python scripts/generate_test_video.py` 生成（无音轨，用于上传/抽帧/OCR 链路，不用于证明 ASR）。

## 5. 数据与清理

- 上传：`$VIDEO_SERVICE_DATA_DIR/uploads`
- 任务与 SQLite：`$VIDEO_SERVICE_DATA_DIR/jobs.sqlite3`
- 抽帧和解析产物：`$VIDEO_SERVICE_DATA_DIR/jobs/{job_id}`
- 默认成功保留 30 天、失败 14 天；queued/processing 永不清理。

```bash
python scripts/cleanup_video_jobs.py --data-dir /var/lib/adsure-video --dry-run
python scripts/cleanup_video_jobs.py --data-dir /var/lib/adsure-video
```

## 6. 资源与限制

CPU 模式无需 GPU。systemd 初始建议 2 CPU、4 GB 内存上限；16 秒视频在 Apple Silicon 上约 15–25 秒，Ubuntu x86 需以 smoke 实测。单视频默认 512 MB、30 分钟、最多 1800 采样帧。RapidOCR 本地运行；ASR 默认本地 dual，火山 provider 必须显式配置和授权。

## 7. 已知限制

当前 SQLite + 单 worker/单 uvicorn 进程适合比赛和单机试运行，不支持多副本同时抢同一任务。VLM/云端 ASR 的授权仍按任务显式开关；视频服务不保存密钥到任务结果。真实 ASR 模型初始化和 Linux x86 速度仍需在云服务器完成验收。

## 8. 依赖与资源规格

| 项目 | 规格 |
| --- | --- |
| Python | 3.11+（本机开发为 3.12） |
| ffmpeg/ffprobe | 最低 4.4；用于诊断与部分容器场景。主抽取链路使用 PyAV(av) + OpenCV，不通过 shell 调 ffmpeg |
| OCR | RapidOCR `rapidocr-onnxruntime>=1.4`（PP-OCRv4 ONNX，约 15 MB，首次运行随 pip 包内置模型，无需单独下载） |
| ASR 主引擎 | faster-whisper `>=1.2,<2`，模型 medium（约 1.5 GB，`data/video_mvp/models/medium`） |
| ASR 复核 | sherpa-onnx SenseVoice int8（约 900 MB，`data/video_mvp/models/sensevoice`） |
| 视觉语义 | 默认 local；配置云端后为 Doubao `doubao-seed-2-1-pro-260915`，仅发送 ≤12 精选帧 |
| GPU | 不需要，全部支持 CPU 推理 |
| 最低内存 | 4 GB（systemd MemoryMax=4G）；推荐 8 GB（双 ASR + OCR 并发更稳） |
| 磁盘 | 模型约 2.5 GB；单任务（30 秒视频）抽帧+音频约 50–150 MB；最低保留 2 GB 空闲 |
| CPU 速度（参考） | 16 秒视频在 Apple Silicon 约 15–25 秒；x86 Ubuntu 以 smoke 实测为准 |

## 9. 覆盖状态词表

`coverage` 中各模块使用稳定状态词，`/ready` 与 evidence 均按此输出：

- audio：`transcribed / no_audio_track / audio_track_silent / asr_failed / asr_not_installed / asr_disabled / unknown`
- frames：`sampled_complete / frame_sampling_incomplete / frames_not_executed`
- ocr：`executed / ocr_not_executed`
- visual_semantics：`analyzed / vlm_not_configured / cloud_unauthorized / cloud_call_partial / cloud_call_failed / local_vlm_not_ready / vlm_disabled`
- rule_engine：`completed / failed / not_configured / not_called`
- overall：`complete / partial / not_proven / failed`

## 10. 云端外发授权

上传接口表单 `cloud_consent_endpoint` 为空时强制本地处理，不发送任何帧或音频。云端 ASR（火山 bigmodel）由 `VIDEO_MVP_ASR_ENGINE=volc` 开启；视觉帧仅当该字段等于已配置的云端 endpoint 时才发送。目标地址、模型名、发送范围、每帧/音频 SHA256 均写入任务目录留痕。

## 11. 回滚

```bash
sudo systemctl stop adsure-video
# 回到上一个 commit
cd /opt/adsure-video-review && sudo -u adsure git checkout <previous-sha>
sudo -u adsure .venv-video/bin/pip install -r requirements-video.txt
sudo systemctl start adsure-video
```

SQLite 表结构通过幂等迁移自动补列；如需回退数据库，可直接用部署前备份的 `/var/lib/adsure-video/jobs.sqlite3` 覆盖（先停服务）。
