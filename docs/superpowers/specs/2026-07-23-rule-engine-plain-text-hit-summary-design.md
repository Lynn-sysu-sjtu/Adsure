# 规则引擎纯文本命中要点设计

日期：2026-07-23  
范围：`Adsure/rule_engine`  
状态：用户已确认

## 1. 背景

当前规则引擎使用 `_precheck_hit_summary()` 同时生成：

- `预审_命中要点`；
- `审核_高风险词命中`。

该函数输出的是带规则编号的规则列表，例如：

```text
命中规则：[GAME-FALSE-004] 禁止虚假广告（虚假宣传·高）
```

飞书法务通知卡会将 `预审_命中要点` 直接放入 `lark_md`。方括号形式的规则编号可能与 Markdown 语法发生冲突。同时，该字段名称表达的是面向运营和法务的“风险摘要”，而不是技术规则列表，当前输出也不符合字段的产品语义。

飞书侧已单独处理卡片发送不得静默失败。本次只修改规则引擎内部展示字段，不修改飞书状态机。

## 2. 目标

1. `预审_命中要点` 返回面向人的纯文本风险摘要；
2. `审核_高风险词命中` 返回纯文本原文证据摘要；
3. 两个字段均不得包含规则 ID、Markdown 方括号或原始正则；
4. `matched_rules` 和完整 `审核_审核意见` 继续保留规则 ID，满足法务追溯；
5. `/audit` 字段名称、类型、风险、路由和规则适用结果保持不变。

## 3. 字段语义

### 3.1 `预审_命中要点`

该字段是卡片级简要结论，而不是规则明细。

生成优先级：

1. 优先选择第一条 `confirmed_violation`；
2. 没有确定违规时，选择第一条 `needs_fact_verification`；
3. 如同时存在确定违规和事实核验，可追加一条重要事实核验；
4. 没有最终适用规则时返回“无明显命中”。

单条规则摘要优先使用：

1. `material_evidence`；
2. `applicability_reason`；
3. `missing_facts`；
4. 规则标题作为兼容兜底。

输出要求：

- 使用自然语言；
- 不出现 `[RULE-ID]`；
- 不出现 `regex:`；
- 不生成 Markdown 链接或列表语法；
- 不把内部召回渠道、分数或场景 ID 暴露给用户。

示例：

```text
“爆率拉满”“神装随便出”可能使玩家形成高概率或必然获得装备的预期，需核验游戏实际奖池、概率、保底和适用条件资料。
```

```text
“和狗一样跑过来”将消费者作贬损性比喻，违背社会良好风尚；同时需核验产品是否具备美白功效宣传资质。
```

### 3.2 `审核_高风险词命中`

该字段用于展示能够从物料中定位的高风险原文证据，不再复用规则列表。

生成规则：

- 收集最终规则的 `material_evidence`；
- 去重后使用中文顿号连接；
- 不包含规则 ID、规则标题、正则或 Markdown；
- 没有可用原文证据时返回“无”。

示例：

```text
爆率拉满、神装随便出
```

如现有涵摄只返回更长的连续证据，可以保留该连续证据，不进行可能改变原意的模型式改写。

## 4. 追溯信息保留

本次不删除任何结构化追溯信息：

- `matched_rules[*].rule_id` 保持不变；
- `matched_rules[*].rule_uid` 保持不变；
- `审核_审核意见` 继续显示 `[RULE-ID]` 和规则标题；
- `rule_judgments` 继续保存适用状态、证据和理由；
- 法律依据展示保持不变。

因此，卡片摘要对人友好，完整审核意见和结构化结果仍可用于法务审计。

## 5. 兼容性边界

不修改：

- `/audit` URL；
- 请求字段；
- 响应字段名称和数据类型；
- 飞书字段名称；
- 风险等级枚举；
- 运营/法务路由；
- 候选召回、规则治理和 DeepSeek 涵摄逻辑；
- 事实核验状态；
- RAG 服务。

只修改两个现有字符串字段的内容生成方式。

## 6. TDD 设计

### 6.1 游戏爆率

输入：

```text
开局十连抽，爆率拉满，神装随便出
```

断言：

- `预审_命中要点` 包含概率或事实核验语义；
- 不包含 `GAME-FALSE-004`、`[`、`]`、`regex:`；
- `审核_高风险词命中` 包含原文风险证据；
- `matched_rules` 仍包含 `GAME-FALSE-004`。

### 6.2 美妆侮辱

输入：

```text
我们的美白精华一降价你还不是和狗一样跑过来
```

断言：

- `预审_命中要点` 包含“和狗一样跑过来”或贬损/良好风尚语义；
- 不包含 `GEN-GOOD-CUSTOMS-001` 和 Markdown 方括号；
- `matched_rules` 和完整审核意见仍包含该规则 ID。

### 6.3 普通果汁治癌

输入：

```text
治疗肝癌、肺癌、结肠癌等 80%-90%癌症病类
```

断言：

- `预审_命中要点` 包含疾病治疗风险；
- `审核_高风险词命中` 包含原文治疗宣称；
- 两个卡片字段均不包含规则 ID 或 Markdown 方括号。

### 6.4 契约回归

- 所有原有 `/audit` 必需字段继续存在；
- 字段类型保持字符串；
- 完整审核意见继续保留规则 ID；
- 现有规则身份、涵摄、风险和路由测试继续通过；
- 全量单元测试通过。

## 7. 异常与兜底

- 适用规则缺少 `material_evidence` 和 `applicability_reason` 时，使用规则标题生成纯文本兜底，但删除方括号式规则 ID；
- 摘要生成不得抛出异常影响 `/audit`；
- 涵摄失败仍执行现有人工复核降级，不由本次逻辑改变；
- 不使用新的 LLM 调用生成摘要，避免增加时延和不稳定性。

## 8. 验收标准

1. 卡片使用的两个字段不包含 `[RULE-ID]`；
2. 游戏、美妆和普通果汁三个代表案例仍能清楚表达核心风险；
3. 结构化规则和完整审核意见仍可追溯规则 ID；
4. `/audit` 契约完全不变；
5. 定向测试和全量测试通过。
