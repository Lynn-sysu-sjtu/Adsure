# 游戏概率广告判断节点设计

## 目标

在不新增非《广告法》规则、不改变 `/audit` 输入输出契约的前提下，增强现有 `GAME-FALSE-004` 对抽卡、掉落、爆率和随机奖励广告的召回与涵摄指引，形成两个法律判断节点：

1. 概率及关键条件未披露是否导致广告整体引人误解；
2. 概率宣传是否与游戏实际奖池、掉落概率和保底机制不符。

## 法律边界

本次不把《广告法》解释为对所有网络游戏设定了独立、无条件的概率公示义务。`GAME-FALSE-004` 仍以《广告法》第二十八条为依据，审查的是：

- 广告已对随机奖励的概率或获取难度作出具体或强烈表示；
- 广告未说明足以影响用户下载、充值或抽取决策的概率、奖池、保底次数、适用对象或活动期限；
- 该遗漏或宣传与实际机制不符，可能使消费者对获取概率和获取难度产生错误认识。

因此，规则和输出文案使用“概率及关键条件披露不足导致误导风险”，不使用“违反《广告法》概率公示义务”。

## 规则资产变更

只修改 Adsure 正式规则库中的游戏《广告法》规则文件：

`rule_engine/jsonbase/游戏/20260705_中华人民共和国广告法（2021修正）_2021.04.29生效_20260615下载_规则拆解_v1.json`

在 `GAME-FALSE-004` 内完成以下变更：

- 保留原 `rule_id`、`rule_uid`、法律依据、风险等级和父规则结构；
- 将 `semantic_role` 保持为 `fallback`，避免改变全局召回策略；
- 新增并启用如下场景向量，每个 `vector_text` 保持简短、单一语义：
  - `loot_rate_exaggeration`：夸大抽卡或装备掉落概率；
  - `guaranteed_reward_claim`：将随机奖励表述为必然获得；
  - `probability_conditions_omitted`：高概率宣传未说明奖池、保底、期限等关键条件；
  - `loot_pool_mismatch`：广告展示的稀有道具不在实际奖池或实际极难获得；
  - `guarantee_conditions_hidden`：“十连必出”等承诺隐藏累计次数、新用户或付费门槛。
- 调整 `semantic_criteria` 和 `decision`，要求先核对客观机制，再区分 `needs_fact_verification` 与 `confirmed_violation`；
- 扩充 `fact_check.required_materials`，覆盖概率公示页、实际奖池、各等级掉落概率、保底机制、活动期限和适用对象。

不修改 `GEN-FALSE-001`，避免通用虚假宣传规则与游戏专项规则同义膨胀。

## 召回与涵摄流程

1. 关键词、正则、智谱场景向量和现有开放规则目录召回按现有链路执行。
2. `GAME-FALSE-004` 可由“爆率”等词面信号或新增场景向量进入候选池。
3. 父规则去重后，DeepSeek 只看到一条 `GAME-FALSE-004`，场景命中仅作为规则适用线索。
4. 没有游戏实际机制资料时，输出 `needs_fact_verification`，不直接认定虚假广告。
5. 当请求上下文已提供连续原文证据且显示广告承诺与实际机制明显不符时，允许输出 `confirmed_violation`。

## 测试设计

### 规则资产测试

扩展 `test_semantic_scenario_assets.py`，验证：

- `GAME-FALSE-004` 存在上述五个场景；
- 场景全部启用；
- `vector_text` 长度符合现有限制；
- 不会生成新的父规则 ID。

### Baseline 案例

在现有 baseline 资产中新增或固化：

```text
文案：开局十连抽，爆率拉满，神装随便出
期望父规则：GAME-FALSE-004
期望状态：needs_fact_verification
期望材料：概率公示、奖池配置、掉落概率、保底机制、活动期限与适用对象
```

添加一个已给出反证的单元测试上下文：

```text
广告：十连必出SSR
已知事实：实际需要累计抽取200次才触发保底
期望状态：confirmed_violation
```

真实 DeepSeek 结果存在概率性，因此自动单元测试主要锁定规则资产、候选召回、父规则去重和 `/audit` 契约；真实模型 baseline 作为最终验收而不作为不稳定的单元测试。

## 兼容性

- `/audit` 请求字段、响应字段、风险值和路由字段保持不变；
- `matched_rules` 仍返回原 `GAME-FALSE-004` / `rule_uid`；
- 场景 ID 只在规则引擎内部用于向量索引和调试；
- 飞书状态机无需改动；
- 重建向量后的索引仍按现有父规则合并逻辑返回候选。

## 验收标准

1. “开局十连抽，爆率拉满，神装随便出”可通过新增场景向量召回 `GAME-FALSE-004`。
2. 缺少实际概率和奖池资料时，DeepSeek 不直接认定虚假，而是输出 `needs_fact_verification`。
3. 已有连续原文证据证明广告承诺与实际机制不符时，可输出 `confirmed_violation`。
4. `GAME-FALSE-004` 父规则在 `matched_rules` 中最多出现一次。
5. 现有规则资产、语义召回和 `/audit` 契约测试全部通过。
6. 智谱向量索引重建后，索引维度与场景数量校验通过。

## 不在本次范围

- 不纳入文市发〔2016〕32号、Apple、Google Play 或广告投放平台规则；
- 不新增“游戏概率公示”父规则；
- 不修改 `GEN-FALSE-001`；
- 不修改父规则去重算法、DeepSeek 调用方式或飞书端逻辑；
- 不改变现有风险合成和路由规则。
