## 二、待办

### 已明确的下一步（按优先级）

#### NEXT-1：建 predictor.py — 规则召回 + 一次性分流
- **目标**：运营触发 AI 审核后，系统调用 predictor 做关键词召回，产出统一 JSON，回写 ②预审段（运营视角）+ ③审核段（法务视角）
- **分流逻辑**：读 `data/regulations.json` 中的 `default_routing`，决定飞书通知发给谁
  - `运营`：发飞书通知给运营，提示自行修改，**不通知法务**
  - `法务`：状态推"待法务复核"，**此时才发飞书通知给法务**
  - `运营补资料`：通知运营补充材料（备案文件/版号等）
- **内核**：过渡期用关键词正则匹配（`regulations.json` 的 `keywords` 字段）；后期换队友引擎 API 只改 predictor 内核，worker/app 不动
- **产出字段**（统一 JSON → 拆到两段）：
  - ② 预审段：`风险等级` / `命中要点` / `修改建议`
  - ③ 审核段：`审核意见` / `关键实体` / `高风险词` / `推荐违规类型` / `推荐风险等级`

#### NEXT-2：改 worker.py 触发机制
- **现状**：worker 监听"状态=空且物料非空"（一提交就触发）
- **目标**：改为监听运营**主动触发**信号（`①运营·是否启用AI预审 = "是"`），触发后才调 predictor
- **过渡方案**：运营在多维表格下拉选"是"=触发；等飞书卡片按钮就绪后切换为卡片回调，worker 逻辑不变

#### NEXT-3：飞书机器人互动卡片（AI 审核触发按钮）
- **目标**：运营通过机器人发送的互动卡片按钮触发 AI 审核，替代手动改字段
- **依赖**：需要公网可访问的回调 URL
- **开发阶段**：用 ngrok（`ngrok http 5001` → 临时公网 URL → 填到飞书开放平台）
- **演示/正式**：部署到云服务器（固定 IP，稳定）
- **卡片交互流程**：
  1. 运营在机器人菜单点"提交物料" → 机器人发提交引导卡片
  2. 运营填完多维表格后回复机器人 → 机器人发"确认开启AI审核"卡片
  3. 运营点按钮 → 飞书 POST 回调到我们服务器 → 触发 predictor → 通知分流

#### NEXT-4：上下文重建模块
- **目标**：predictor 在做关键词召回前，先把"物料内容 + 行业专属字段 + ①运营·补充背景资料"拼成完整上下文
- **现状**：字段已全部就位（含 2026-06-26 新加的补充背景资料字段）
- **依赖**：NEXT-1 完成后扩展
