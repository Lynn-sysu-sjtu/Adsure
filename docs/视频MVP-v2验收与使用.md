## 现在怎样运行

这台电脑已经安装 `.venv-video` 和本地 Whisper medium 模型。打开 macOS 终端：

```bash
cd "/Users/lcdat/Documents/广告合规AI"
```

改端口后打开 http://127.0.0.1:8511 。若已有旧版服务，在其终端按 `Control+C` 后再启动本版。
网页上传的本地任务写入 `data/video_mvp/jobs/<任务编号>/`。旧报告不会自动升级，请重新提交视频。

### 新机器首次安装

要求 macOS、Python 3.12、Xcode Command Line Tools（可用 `xcode-select -p` 检查）。
首次安装系统编译工具时运行 `xcode-select --install`，按系统提示完成。

```bash
cd "/Users/lcdat/Documents/广告合规AI"
python3.12 -m venv .venv-video
.venv-video/bin/python -m pip install -r requirements-video.txt
.venv-video/bin/python -m src.video_mvp.asr --download-model medium
make video-mvp
```

本机验证使用 `/opt/anaconda3/bin/python3.12` 创建的、复用现有依赖的虚拟环境；上面的独立环境安装路径未在另一台干净机器验证。
模型权重约 1.5 GB，首次下载需要网络。默认 `medium`，保存在 `data/video_mvp/models/medium/`。
依赖和模型就绪后，审核使用本地推理，视频和音轨不发送至云服务，也不需要 API Key。
解码由 PyAV/OpenCV 完成，不依赖单独的 FFmpeg 命令。
模型来源：[SYSTRAN faster-whisper](https://github.com/SYSTRAN/faster-whisper)。

### 不使用网页

```bash
cd "/Users/lcdat/Documents/广告合规AI"
.venv-video/bin/python -m src.video_mvp.cli "/绝对路径/待审视频.mp4" \
  --output "data/video_mvp/manual_run_v2" \
  --industry 化妆品 --sample-interval 0.5 --max-frames 1800
```

每次使用新输出目录，保留前次证据。可添加 `--transcript /绝对路径/字幕.srt`；它是补充证据，不会关闭自动转写。
`--asr off` 可仅分析画面，但口播覆盖会明确降级，不能当作完成审核。
可用行业：一般行业、保健食品、普通食品、化妆品、教育培训、金融投资、医疗、药品、医疗器械；选项存在不代表该行业专项规则已完整覆盖。

可配置：`VIDEO_MVP_ASR_MODEL`（本地模型目录）、`VIDEO_MVP_ASR_THREADS`（默认 4）、
`VIDEO_MVP_ASR_TIMEOUT`（默认 900 秒）、`VIDEO_MVP_MAX_FRAMES`（网页默认 1800）。
本版网页串行处理任务；CPU 推理耗时与视频、配乐和机器负载有关，不能按视频时长保证 SLA。
当前单段上限 30 分钟。不要将无鉴权的本地服务直接暴露到公网。
Apple Vision 若提示执行失败，请在普通 macOS 终端运行，并检查 `/health` 和报告里的原始错误；隔离沙箱可能无法使用系统 Vision 资源。

## 修复了什么

| 原因 | v2 行为 | 仍存在的限制 |
| --- | --- | --- |
| 原版没有自动 ASR，无字幕就没有口播证据 | 自动解码全部音轨，本地转写，保留句/词时间戳、原始结果和模型哈希记录 | 噪声、方言、专有词和多人重叠仍可能错；不是说话人身份识别 |
| 固定间隔、关键帧跳转可能遗漏短暂内容 | 0.5 秒基线，约 0.1 秒变化探测，保留变化前后与尾帧；顺序解码避免跳错关键帧 | 短于探测间隔、小幅低对比变化仍可能漏掉；不是逐帧审核 |
| 只匹配单句/单行，行业选错便跳过医疗表达 | 繁简/全半角/空白归一化，时空相邻 2–3 段窗口，保留原始证据 ID | 不做任意模糊纠错；语义改写与 ASR 错词仍可能漏检 |
| “第一步”等无关内容屏蔽同段风险 | 使用局部否定与相邻语境，不用整段豁免 | 反问、引述与复杂否定仍需人工判断 |
| 规则维度过少，领取承诺未触发核验 | 10 类候选模板：绝对化两类、医疗、功效安全、量化效果、背书、投资、培训、贬损、赠送承诺 | 是线索库，不是完整法律/平台规则库；不得把“触发核验”说成违法 |
| OCR/ASR 失败仍像成功报告 | 分别输出画面/音轨覆盖；失败、低置信度和预算漏采触发 `needs_attention` | 分数较高也会转错；完整采样不等于完整风险覆盖 |
| RAG 查询被开头大量无关 OCR 淹没 | 优先以实际命中及其原始证据构造检索问题 | 没有相关案例时留空，不制造案例或拿案例代替商品事实 |

赠送承诺是材料核验项，不是“免费”违禁词：需核对领取条件和实际兑现；属于附带赠送时，还需检查法定披露事项。
依据是《广告法》第八条第一、二款，[市场监管总局官方文本](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_5474cf75173c45d6a0379730fb4e8d97.html)。

## 达到实际可用，还必须做什么

1. **建立真实漏检验收集**：收集至少 50–100 条经授权的真实广告，人工标注准确口播、画面时间点、风险/非风险和依据；分开开发与盲测集。分别统计转写错字率、关键主张召回、抽帧漏采、风险召回/误报、定位误差、失败率、耗时。当前两条视频和工程例子远不足以证明商用可用。
2. **补语义与音频难例处理**：评测中文专项 ASR、专有词词表、降噪/人声分离与更强模型；保留原始转写，纠错结果单独留痕。接入受约束的多模态语义候选提取，覆盖画面动作、暗示、前后对比与字幕/口播冲突。不得只让模型直接给“通过/不通过”。
3. **从关键词核验走向材料核验**：把产品备案/资质、功效证据、赠品活动规则、落地页、实际游戏或商品功能接进来；没有材料应输出“无法核验”，不能以案例相似或模型常识代替。
4. **完善法律与平台规则生命周期**：每条记录适用主体/行业、规则类型、条款或章节定位、官方来源、采集日期、有效/版本状态和例外。当前网页填写平台名只辅助案例检索，尚未接通仓库中的平台预检流程；不能宣称已完成抖音/小红书专项审核。
5. **人工复核闭环与运行可靠性**：支持校正转写、复核命中/误报/漏报，重跑并保留版本；建立重启后任务恢复、取消/重试、容量与耗时限制、身份隔离和访问审计。当前后台队列不是持久化任务系统。

音乐、视频 DNA、IP 与字体需要权利库或外部服务及授权资料，本次没有虚构接通。
正确目标是“有证据可核验的风险尽量召回，证据不足明确暴露”，不是保证每条广告都有风险或承诺全部风险查全。
