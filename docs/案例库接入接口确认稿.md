# 案例库接入接口确认稿

> 版本：v1.0
> 日期：2026-07-18
> 对接范围：飞书状态机、法务工作台、规则引擎、广告处罚案例库
> 本文为联调唯一口径；队友原始文件保留不改。

## 0. 先确认三件事

### 0.1 `/audit` 和 `/cases/retrieve` 是两个接口

- `POST /audit`：规则引擎审核接口。飞书状态机点击“开启 AI 审核”时调用，返回风险、审核意见、命中规则和 `routing`。
- `POST /cases/retrieve`：案例库检索接口。法务工作台打开物料详情时调用，返回可展示的相关案例。

案例库接口不负责决定 `routing`，规则引擎接口也不应把“相似案例”直接当作违法结论。

### 0.2 队友不会把飞书原始字段对象直接传给案例库

飞书侧会先把 `①运营·物料内容` 等中文字段转换成标准化 JSON。案例库只接收标准字段，不接收：

```json
{
  "fields": {
    "①运营·物料内容": "..."
  }
}
```

### 0.3 当前仓库还没有 HTTP 接口

当前代码已经具备：

- 从结构化案例构建 `case_summary` 和 `regulatory_logic` 两类切片；
- 使用自然语言 `vector_text` 生成案例摘要切片；
- 对切片执行本地 BM25 词法检索；
- 输出带来源、审核状态和候选状态的检索结果。

当前代码尚不具备：

- Flask、FastAPI 或其他 HTTP 服务；
- `POST /cases/retrieve` 路由；
- embedding 生成、向量数据库或余弦相似度；
- 将检索切片补全为队友案例卡片字段的适配层。

因此下文 `/cases/retrieve` 是双方已经可以据此开发和联调的目标契约，不应表述为本仓库已经上线。

## 1. 完整调用关系

### 1.1 AI 审核主链路

```text
运营点击“开启 AI 审核”
  → 飞书后端整理标准化 payload
  → POST /audit
  → 规则引擎执行规则召回与审核
  → 飞书回写 ②AI预审、③AI审核字段
  → 根据 routing 流转到运营或法务
```

### 1.2 相关案例展示链路

```text
用户打开物料详情
  → 法务工作台 GET /api/records/<record_id>/cases
  → 工作台从飞书记录取得 content、industry、platform
  → 工作台后端 POST /cases/retrieve
  → 案例库执行召回并返回 cases
  → 工作台展示“相关案例参考”卡片
```

前端不直连案例库。案例库 URL 和凭证只配置在工作台后端。

## 2. 飞书调用 `/audit` 时发送什么

### 2.1 标准请求体

```json
{
  "record_id": "rec_xxx",
  "mode": "标准",
  "industry": "美妆",
  "content": "15天见效，全网第一，焕发新生",
  "urgency": "普通",
  "supplement": "",
  "platform": ["小红书"],
  "material_type": "图文",
  "product_category": "护肤",
  "extras": {
    "产品备案名称": "某产品备案名称",
    "核心宣称功效": "提亮",
    "物料涉及场景": "信息流广告"
  }
}
```

### 2.2 字段约定

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `record_id` | string | 是 | 飞书记录 ID，用于回写和全链路排查 |
| `mode` | string | 是 | 当前使用 `标准`；后续可扩展 `极速`、`深度` |
| `industry` | string | 是 | `美妆`、`游戏`、`保健食品`或`通用` |
| `content` | string | 是 | 完整待审物料文本；空字符串应返回参数错误 |
| `urgency` | string | 是 | `普通`或`加急` |
| `supplement` | string | 是 | 补充背景；没有时传空字符串 |
| `platform` | string[] | 是 | 多选字段必须传数组 |
| `material_type` | string | 是 | 如`图文`、`短视频`、`Banner`、`直播话术` |
| `product_category` | string | 是 | 产品或服务类别 |
| `extras` | object | 是 | 行业专属信息；没有时传空对象 |

行业专属 `extras`：

- 美妆：`产品备案名称`、`核心宣称功效`、`物料涉及场景`；
- 保健食品：`产品备案名称`、`批准文号`、`核心宣称功效`、`物料涉及场景`；
- 游戏：`游戏名称`、`IP名称`、`物料涉及场景`。

### 2.3 `/audit` 调用约定

```text
POST <RULE_ENGINE_URL>/audit
Content-Type: application/json
X-API-Key: <通过安全渠道提供，不写入文档或仓库>
timeout: 10 秒
```

飞书侧当前约定：

- 超时不自动重试，由运营重新触发；
- `code != 0`、超时或网络异常时回退到“运营起草”；
- 不写入 ②、③ 段审核字段；
- 向运营展示红色失败卡片；
- 状态为“AI预审中”时拦截重复点击。

## 3. 法务工作台调用 `/cases/retrieve` 时发送什么

### 3.1 请求

```text
POST <CASE_ENGINE_URL>/cases/retrieve
Content-Type: application/json
X-API-Key: <通过安全渠道提供，不写入文档或仓库>
timeout: 8 秒
```

```json
{
  "content": "待审物料文案全文",
  "industry": "美妆",
  "platform": ["抖音", "小红书"],
  "top_k": 3
}
```

### 3.2 请求字段

| 字段 | 类型 | 必填 | 接收规则 |
| --- | --- | --- | --- |
| `content` | string | 是 | 去除首尾空白后不能为空，最大长度由服务端配置 |
| `industry` | string | 是 | 首期接受`美妆`、`游戏`、`保健食品`、`通用` |
| `platform` | string[] | 否 | 缺省为 `[]`；必须是字符串数组 |
| `top_k` | integer | 否 | 默认 3，最小 1，最大 5 |

案例库不需要接收 `record_id` 才能检索。为便于链路追踪，后续可以增加可选 `request_id`，但不应将飞书记录 ID 写入案例正文或索引。

## 4. 我方如何触发案例召回

## 4.1 当前代码的真实召回机制

当前实现位于 `src/test_retrieval.py`：

1. 将查询和案例切片转为小写；
2. 中文按单字切分，同时生成相邻双字 bigram；
3. 对每个切片计算 BM25 分数；
4. 按 BM25 分数降序返回前 `top_k` 个切片。

当前不是向量召回：

- `vector_text` 是自然语言案例场景文本；
- 代码没有生成 embedding；
- 没有向量数据库；
- 返回的 `score` 是 BM25 原始分数，不在 0—1 范围内；
- 不能把 BM25 `score` 直接作为前端百分比 `similarity`。

## 4.2 当前索引选择行为

未显式指定切片文件时，当前测试代码会：

1. 查询含游戏、美妆、化妆品、保健品、普通食品、会销、概率等赛道词时，使用 `sector_candidate_chunks.json`；
2. 否则依次尝试 `candidate_chunks.json`、`production_chunks.json`、测试索引和样例索引。

这是开发期测试路由，不可直接用于生产接口，因为它会优先命中未核验候选案例。

## 4.3 `/cases/retrieve` 应采用的正式召回流程

接口适配层应按以下顺序执行：

1. 校验 `content`、`industry`、`platform`、`top_k`；
2. 生成自然语言查询：

   ```text
   行业：美妆。投放平台：抖音、小红书。广告内容：待审物料文案全文。
   ```

3. 按服务端环境配置选择索引：
   - 生产环境：只允许 `production_chunks.json`；
   - 隔离联调环境：可以显式使用候选索引，并在响应中标记 `candidate_data=true`；
   - 生产索引为空时返回空数组，不得自动回退候选索引。
4. 对选择的切片执行 BM25 召回；
5. 同一 `case_id` 的 `case_summary` 和 `regulatory_logic` 命中结果去重，只保留最高分作为排序分；
6. 根据 `case_id` 回读完整结构化案例，补齐处理结果、法律依据、原始宣称和来源字段；
7. 将内部案例字段转换为接口字段；
8. 返回最多 `top_k` 个案例。

平台在首期只用于构造查询和展示，不作为硬过滤条件。只有当案例平台字段完成规范化后，才能启用平台硬过滤。

## 5. `/cases/retrieve` 返回什么

### 5.1 成功响应

以下仅为字段结构示例，不代表真实案例：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "cases": [
      {
        "case_id": "case_xxx",
        "title": "案例标题",
        "content_snippet": "原案例广告宣称或与查询最相关的案例片段",
        "industry": "美妆",
        "platform": ["某投放渠道"],
        "violation_type": "违规类型",
        "risk_dimensions": ["风险维度"],
        "risk_level": null,
        "ruling": "处理结果摘要",
        "legal_basis": ["经来源核验的法律依据"],
        "regulatory_logic": "监管机关认定风险的逻辑摘要",
        "score": 12.345,
        "score_type": "bm25",
        "similarity": null,
        "source_name": "公开来源名称",
        "source_url": "https://example.invalid/case",
        "raw_text_path": "data/raw_text/case_xxx.json",
        "review_status": "approved",
        "source_verification_status": "source_verified",
        "approved_for_rag": true,
        "candidate_data": false
      }
    ],
    "retrieval_meta": {
      "index_scope": "production",
      "top_k": 3,
      "returned": 1
    }
  }
}
```

### 5.2 返回字段来源和当前可用性

| 返回字段 | 内部来源 | 首期要求 | 说明 |
| --- | --- | --- | --- |
| `case_id` | 案例 `case_id` | 必返 | 案例唯一 ID |
| `title` | 案例 `title` | 必返 | 案例标题 |
| `content_snippet` | `illegal_claims`，无值时取相关切片 | 必返 | 最长 150 字；不得补写原文没有的宣称 |
| `industry` | `metadata.industry` | 必返 | 案例所属行业 |
| `platform` | `metadata.ad_channel` | 必返 | 有值时作为单元素数组返回；无值返回 `[]` |
| `violation_type` | 案例或 `metadata.violation_type` | 可空 | 不用 `risk_dimensions` 冒充 |
| `risk_dimensions` | 案例 `risk_dimensions` | 必返 | 数组 |
| `risk_level` | 当前案例库无稳定字段 | 可空 | 不得根据相似度推导高、中、低 |
| `ruling` | 完整案例 `penalty_result` | 可空 | 不得把 `regulatory_logic` 冒充裁决 |
| `legal_basis` | 完整案例 `legal_basis` | 必返数组 | 缺失时返回 `[]`，不得补写法条 |
| `regulatory_logic` | 完整案例 `regulatory_logic` | 可空 | 监管逻辑摘要 |
| `score` | BM25 排序分 | 必返 | 原始分数，不是百分比 |
| `score_type` | 固定 `bm25` | 必返 | 便于前端正确解释 |
| `similarity` | 真实余弦相似度 | 可空 | 当前未实现 embedding，应返回 `null` 或省略 |
| `source_name` | 案例 `source_name` | 必返 | 来源名称 |
| `source_url` | 案例 `source_url` | 必返 | 生产案例必须为可回溯的 HTTP(S) URL |
| `raw_text_path` | 案例 `raw_text_path` | 必返 | 人工回溯路径 |
| `review_status` | 案例审核状态 | 必返 | 如 `approved`、`pending_review` |
| `source_verification_status` | 来源核验状态 | 必返 | 生产案例应为 `source_verified` |
| `approved_for_rag` | 案例审批状态 | 必返 | 生产结果必须为 `true` |
| `candidate_data` | 索引范围 | 必返 | 候选联调结果为 `true` |

### 5.3 为什么对队友原字段做了调整

- `risk_level`：当前案例库没有稳定的案例风险等级，不能编造。
- `similarity`：当前只有 BM25 分数，不能伪装成 0—1 相似度。
- `legal_basis`：一个案例可能对应多条依据，使用数组比拼接字符串更安全。
- 新增 `source_url`、`raw_text_path` 和审核状态：这是案例人工回溯和候选隔离的硬要求。
- 新增 `risk_dimensions`、`regulatory_logic`：便于法务理解召回原因，但不能替代规则引擎判断。

### 5.4 空结果

没有可用生产案例时：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "cases": [],
    "retrieval_meta": {
      "index_scope": "production",
      "top_k": 3,
      "returned": 0
    }
  }
}
```

法务工作台展示“暂无相关案例”，不影响 AI 审核和状态流转。

### 5.5 参数错误

```json
{
  "code": -1,
  "msg": "缺少必填字段：content",
  "data": null
}
```

建议错误类型：

- `content` 为空；
- `industry` 不在支持范围；
- `platform` 不是字符串数组；
- `top_k` 不是 1—5 的整数；
- API Key 无效或缺失。

## 6. `/audit` 返回什么给飞书

规则引擎成功响应保持队友已经接通的结构：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "resolved_mode": "标准",
    "mode_reason": "MVP阶段统一使用标准审核模式",
    "预审_风险等级": "高",
    "预审_命中要点": "命中要点文本",
    "预审_修改建议": "修改建议文本",
    "审核_审核意见": "完整审核意见",
    "审核_关键实体抽取": "关键实体文本",
    "审核_高风险词命中": "高风险词文本",
    "审核_平台规则预检": "平台规则预检结果",
    "审核_备案核查结果": "备案核查结果",
    "审核_推荐违规类型": ["绝对化用语", "虚假宣传"],
    "审核_推荐风险等级": "高",
    "routing": "法务",
    "matched_rules": [],
    "audit_time": 1784332800000
  }
}
```

字段约定：

| 字段 | 飞书处理 |
| --- | --- |
| `resolved_mode` | 写入③AI审核·审核模式 |
| `mode_reason` | 写入③AI审核·模式推荐理由 |
| `预审_风险等级` | 写入②AI预审·风险等级 |
| `预审_命中要点` | 写入②AI预审·命中要点 |
| `预审_修改建议` | 写入②AI预审·修改建议 |
| `审核_审核意见` | 写入③AI审核·审核意见 |
| `审核_关键实体抽取` | 写入③AI审核·关键实体抽取 |
| `审核_高风险词命中` | 写入③AI审核·高风险词命中 |
| `审核_平台规则预检` | 写入③AI审核·平台规则预检 |
| `审核_备案核查结果` | 写入③AI审核·备案核查结果 |
| `审核_推荐违规类型` | 多选数组；每个值必须已配置为飞书选项 |
| `审核_推荐风险等级` | 写入③AI审核·推荐风险等级 |
| `audit_time` | 毫秒时间戳，同时写入②、③段审核时间 |
| `matched_rules` | 格式化为文本，附加到审核意见末尾 |
| `routing` | 转换为⑤流转·当前状态 |

### 6.1 `routing` 状态映射

| 规则引擎返回 | 飞书状态 | 后续动作 |
| --- | --- | --- |
| `运营` | 待运营修改 | 推送运营修改卡片 |
| `运营补资料` | 待运营修改 | MVP 暂与运营路由相同 |
| `法务` | 待法务复核 | 通知法务 |
| 错误、超时或网络异常 | 运营起草 | 不写审核字段，推送失败卡片 |

当前联调记录显示，规则引擎已有规则默认路由均偏向法务，`routing=运营` 尚需配置可运营处理的规则后再补测。

### 6.2 违规类型枚举

飞书侧已补充规则引擎当前需要的选项。接口必须返回字符串数组，不能返回逗号拼接字符串。

当前规则引擎稳定输出范围包括：

- 绝对化用语；
- 虚假宣传；
- 涉医疗宣传；
- 价格促销误导；
- 平台准入/资质不符；
- 广告代言不合规；
- 广告可识别性不足；
- 引证内容不规范；
- 用户评价/种草误导；
- 未成年人保护；
- 其他。

飞书展示枚举与规则引擎内部维度后续应通过映射表解耦，不应为适配飞书而直接改写规则库维度。

## 7. 两类失败不能混在一起

### 7.1 `/audit` 失败

这是主审核链路失败：

- 飞书状态回退到“运营起草”；
- 不写入审核结果；
- 运营收到失败卡片；
- 允许重新点击触发。

### 7.2 `/cases/retrieve` 失败

这是相关案例辅助展示失败：

- 法务工作台返回 `{"cases": []}` 或等价空结果；
- 页面展示“暂无相关案例”；
- 不修改飞书状态；
- 不影响 `/audit` 已生成的审核结果；
- 工作台后端总超时 8 秒，案例库建议 5 秒内返回。

## 8. 安全要求

1. API Key 只能通过安全渠道和部署环境变量提供；
2. 不得把 Key 写入 Word、Markdown、代码、Git 或完整请求日志；
3. 队友提供的 Word 文件中出现了明文 Key，该 Key 应立即轮换；
4. 新 Key 不在本确认稿中记录；
5. 日志只记录请求 ID、耗时、状态码、索引版本和脱敏摘要；
6. 候选案例不得在生产接口中静默返回。
