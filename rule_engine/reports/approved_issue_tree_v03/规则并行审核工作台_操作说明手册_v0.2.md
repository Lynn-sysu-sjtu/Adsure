# 规则并行审核工作台操作说明手册 v0.2

## 一、适用文件

本手册适用于：

`reports/approved_issue_tree_v03/规则并行审核工作台_DeepSeek预审_中文问题名_v0.3.xlsx`

本轮审核采用“DeepSeek 先预审，人工复核 AI 结论”的方式。人工不需要从零填写全部判断，只需要：

1. 阅读规则原文和现有映射；
2. 阅读蓝色 AI 建议、判断理由和人工复核重点；
3. 判断 AI 是全部准确、部分准确、不准确，还是需要讨论；
4. 只有 AI 存在错误时，才在黄色人工字段中填写修正值；
5. 无法独立判断的规则提交争议池。

本轮结果属于候选审核资产，不会直接修改 `jsonbase`，也不会自动进入生产规则引擎。

## 二、审核目标

每个规则 UID 需要最终解决六个问题：

1. **适用范围是否正确**：规则属于通用、游戏、美妆还是保健食品赛道；
2. **问题归属是否正确**：规则原文是否能支持当前挂载的问题；
3. **映射角色是否正确**：规则是直接依据、辅助依据、例外条件，还是主动核查项；
4. **审核链路是否正确**：规则应进入普通文案召回、事实核验、主动核查、流程参考还是平台准入；
5. **资产处置是否正确**：保留、调整映射、转旁路、不纳入候选资产或待讨论；
6. **是否存在必须集中裁决的争议**。

审核的首要依据始终是“规则原文”。问题名称、规则标题、历史模型结果和本轮 AI 建议都只是辅助信息。

## 三、工作簿结构

| Sheet | 用途 | 是否填写 |
|---|---|---|
| 操作说明 | 查看表内简要说明 | 否 |
| 并行审核主表 | 查看全部 218 个 UID、任务分配和总体进度 | 原则上不填写 |
| 任务包A | 第一位成员审核，共 73 个 UID | 是 |
| 任务包B | 第二位成员审核，共 72 个 UID | 是 |
| 任务包C | 第三位成员审核，共 73 个 UID | 是 |
| 争议池 | 汇总无法独立判断、需要负责人或法务裁决的问题 | 是 |
| 校验结果 | 查看任务唯一性、分工和资产保护状态 | 否 |

每位成员只编辑自己的任务包，不要重新排序整张表，不要修改规则 UID、规则原文、蓝色 AI 字段或其他成员的任务包。

当前 v0.3 的任务包 Sheet 没有单独的“负责人”列。项目负责人应按照“任务包A/B/C”统一分派人员，并在外部分工记录中写明负责人。主表中的“负责人”列不作为本轮成员填写区。

## 四、颜色说明

| 颜色 | 含义 | 操作要求 |
|---|---|---|
| 普通底色 | 规则事实、历史映射和来源信息 | 只读 |
| 蓝色 | DeepSeek 预审建议 | 只读，不直接覆盖 |
| 黄色 | 人工复核和修正字段 | 按本手册填写 |
| 风险提示色 | 规则存在需要重点核对的风险标签 | 结合原文检查，不代表必然有错 |

## 五、审核顺序

### 第一步：确认规则身份

依次阅读：

1. `规则UID`
2. `规则标题`
3. `来源类型`
4. `法规或平台规则`
5. `条款`
6. `规则原文`
7. `来源文件`

检查规则标题是否忠实概括原文，法规名称和条款是否对应，原文是否足以判断适用对象、规制行为和法律效果。标题与原文冲突时，以原文为准。

### 第二步：确认当前问题映射

阅读：

- `当前适用赛道`
- `当前一级问题`
- `当前二级问题`
- `当前全部问题`
- `当前全部问题ID`
- `当前映射角色`

`当前全部问题`用于人工阅读，展示中文问题名称；`当前全部问题ID`用于工程追溯和后续写回。二者应逐项对应。

### 第三步：阅读 AI 建议

重点阅读：

- `AI建议适用赛道`
- `AI建议保留问题名称`
- `AI建议删除问题名称`
- `AI建议最终映射角色`
- `AI建议最终审核链路`
- `AI建议资产处置`
- `AI建议提交争议池`
- `AI判断理由`
- `AI人工复核重点`

不要因为 `AI置信度=high` 就直接通过。高置信度只代表模型对自身判断较有把握，不代表判断必然正确。

### 第四步：作出人工复核结论

在 `人工复核AI结论` 中选择：

| 选项 | 含义 | 后续填写方式 |
|---|---|---|
| 全部准确 | AI 的赛道、问题映射、角色、链路、处置和争议池判断均正确 | 其他人工修正字段可以留空 |
| 部分准确 | AI 的主要方向正确，但一个或多个字段需要修改 | 只填写需要修正的字段，并说明差异 |
| 不准确 | AI 的核心问题归属、角色、链路或资产处置明显错误 | 填写完整的正确结论和理由 |
| 需讨论 | 现有资料不足，或审核人无法独立作出稳定判断 | 审核状态选“待讨论”，提交争议池 |

### 第五步：完成状态和二审标记

- 已作出结论：`审核状态=已完成`；
- 正在审核：`审核状态=审核中`；
- 无法独立判断：`审核状态=待讨论`；
- 涉及移出候选资产、跨目录多重映射或重大法律边界：原则上选择`二审状态=待二审`；
- 填写统一格式的审核日期：`YYYY-MM-DD`。

## 六、全部列名说明

### 6.1 分工与风险字段

| 列名 | 含义 |
|---|---|
| 建议任务包 | 系统根据工作量将 UID 分配到任务包A、B或C |
| 工作量积分 | 根据风险标签估算的相对审核工作量，用于平衡分工，不代表法律风险等级 |
| 风险标签 | 提示该规则需要重点检查的事项，一条规则可同时具有多个标签 |

风险标签含义：

| 风险标签 | 含义 | 审核重点 |
|---|---|---|
| 跨目录重叠 | 同一 UID 当前挂在多个问题节点下 | 判断多重映射是否均有原文依据 |
| 问题错配 | 规则原文可能无法支持当前问题 | 比较规则构成要件与问题定义 |
| 主动补资料 | 规则可能依赖资质、备案、检测、授权等材料 | 判断是否只能生成核查项，而不能直接认定违规 |
| 移出普通文案树 | 规则可能不适合参与普通文案召回 | 判断应进入事实、流程或平台准入旁路 |
| 中低置信度 | 历史模型对问题归属或适用范围把握不足 | 重点核对适用对象、行为结构和边界 |

### 6.2 规则身份与来源字段

| 列名 | 含义 |
|---|---|
| 规则UID | 去重后的规则唯一标识。同一规范文本原则上只保留一个 UID |
| 规则标题 | 对规则原文的简要概括，不能代替原文 |
| 来源类型 | 规则来源类别，例如法律、行政法规、部门规章、规范性文件或平台规则 |
| 法规或平台规则 | 规则来源文件或平台规范的名称 |
| 条款 | 规则在来源文件中的条文位置 |
| 规则原文 | 本轮人工审核的首要依据 |
| 来源文件 | 该规则在本地规则资产中的来源路径，用于追溯 |

### 6.3 当前问题映射字段

| 列名 | 含义 |
|---|---|
| 当前适用赛道 | 当前资产记录的适用赛道，可能存在赛道污染，需要人工复核 |
| 当前一级问题 | 问题树的一级目录，例如宣传真实性、功效与性能宣称 |
| 当前二级问题 | 一级目录下的二级问题分类 |
| 当前全部问题 | 当前 UID 挂载的全部中文问题名称 |
| 当前全部问题ID | 上述问题的稳定工程标识，用于校验和写回，不要求审核人凭英文 ID 理解问题 |
| 当前映射角色 | 当前资产中规则与问题的关系，可能包含待细分的 `legal_issue` |

`legal_issue` 是早期资产加工的过渡标记，只表示“规则已经与某个法律问题建立映射”，没有说明这条规则具体承担什么作用。本轮不得把 `legal_issue` 直接作为最终映射角色，必须细分为下文四种最终角色之一。

### 6.4 历史模型与审核提示字段

| 列名 | 含义 |
|---|---|
| 模型置信度 | 历史问题树加工阶段的模型置信度，不是本轮 DeepSeek 预审置信度 |
| 历史判断理由 | 历史问题指纹、聚类或规则映射阶段留下的判断理由 |
| 审核提示 | 提醒审核人完成哪些检查，不代表最终结论 |

### 6.5 蓝色 AI 预审字段

| 列名 | 含义 |
|---|---|
| AI建议适用赛道 | DeepSeek 根据规则原文建议的最终赛道 |
| AI建议保留问题名称 | AI 认为规则原文能够支持、应继续保留的问题 |
| AI建议删除问题名称 | AI 认为与规则原文不一致或属于冗余映射、应解除的问题 |
| AI建议最终映射角色 | AI 对规则在问题判断中承担作用的分类 |
| AI建议最终审核链路 | AI 建议系统采用的处理路径 |
| AI建议资产处置 | AI 建议对候选资产采取的工程动作 |
| AI建议提交争议池 | AI 是否认为该规则需要集中讨论 |
| AI置信度 | DeepSeek 对本轮整组预审判断的把握程度，分为 high、medium、low |
| AI判断理由 | AI 对适用对象、问题归属、映射角色、审核链路和处置的综合说明 |
| AI人工复核重点 | AI 提醒人工优先确认的边界、冲突或不确定事项 |
| AI模型与提示词版本 | 记录模型和提示词版本，用于追溯和复现 |

AI 置信度选项：

| 选项 | 含义 |
|---|---|
| high | AI 认为规则原文和建议结论之间对应关系较明确 |
| medium | AI 认为主要方向可判断，但存在适用范围、角色或问题边界不确定性 |
| low | AI 无法稳定判断，人工应优先复核，通常需要二审或讨论 |

### 6.6 黄色人工复核字段

| 列名 | 含义与填写要求 |
|---|---|
| 人工复核AI结论 | 每条必填：全部准确、部分准确、不准确或需讨论 |
| 审核状态 | 每条必填：未开始、审核中、已完成或待讨论 |
| 人工结论 | AI 有差异时填写人工最终判断 |
| 正确适用赛道 | AI 赛道错误时填写通用、游戏、美妆或保健食品 |
| 保留问题ID | AI 保留问题不准确时，填写人工确认应保留的完整问题 ID；多个 ID 每行一个 |
| 删除问题ID | AI 删除问题不准确时，填写人工确认应解除的完整问题 ID；多个 ID 每行一个 |
| 最终映射角色 | AI 角色不准确时填写最终角色，不得填写 `legal_issue` |
| 最终审核链路 | AI 链路不准确时填写最终处理链路 |
| 资产处置 | AI 处置不准确时填写最终工程动作 |
| 审核理由 | 部分准确、不准确或需讨论时，写明差异、原文依据和修正理由 |
| 是否提交争议池 | 需要负责人或法务集中裁决时选“是” |
| 二审状态 | 无需二审、待二审、二审通过或退回修改 |
| 二审意见 | 二审人填写同意、修改项和依据 |
| 审核日期 | 使用 `YYYY-MM-DD` 格式 |

人工留空不等于漏填。后续汇总遵循：**人工修正优先；人工修正字段为空时，继承 AI 建议。**

## 七、最终映射角色详解

“映射角色”回答的是：**这条规则在对应问题的法律判断中承担什么作用？**

| 选项 | 中文含义 | 判断标准 | 能否单独形成疑似违规结论 |
|---|---|---|---|
| `direct` | 直接判断依据 | 规则原文直接规定禁止行为、限制条件、披露义务或明确违规要件，物料出现对应行为即可初步判断 | 可以 |
| `supporting_basis` | 辅助或上位依据 | 规则只提供原则、总括要求、定义、责任或上位法支持，不能单独说明个案已经违规 | 不可以 |
| `exception` | 例外或豁免条件 | 规则规定在特定条件下不适用禁止性规定，或允许某种表达、主体、范围或行为 | 不可以；用于排除或缩小违规 |
| `proactive_check` | 主动核查项 | 完整投放需要检查资质、备案、批准文件、授权、证明材料或其他外部事实，但不能因资料暂未展示就直接认定违法 | 不可以；输出核验事项 |

### 角色判断示例

- “保健食品广告不得涉及疾病预防、治疗功能”：通常是 `direct`。
- “广告内容应当真实、合法”：如果仅作为总括性原则支持更具体规则，通常是 `supporting_basis`。
- “普通化妆品通过视觉、嗅觉可直接识别的功效可免予公布摘要”：通常是 `exception`。
- “宣称美白功效时应核验特殊化妆品注册信息”：通常是 `proactive_check`。

同一规则若同时包含多个规范层次，应选择它在当前问题映射中的主要作用，并在审核理由中说明；无法确定时提交二审。

## 八、最终审核链路详解

“审核链路”回答的是：**系统应当怎样处理这条规则？需要哪些输入才能给出结果？**

| 选项 | 中文含义 | 适用情形 | 常见输出 |
|---|---|---|---|
| 普通文案召回 | 内容审核链路 | 仅阅读广告文案或素材即可初步判断是否命中 | 疑似违规问题和法律依据 |
| `fact_check` | 事实核验链路 | 文案已经提出具体事实宣称，但是否成立必须核验检测报告、数据、备案、授权或第三方证明 | 需补资料；材料核验后再确定是否违规 |
| `proactive_check` | 主动核查链路 | 内容层未必已经异常，但基于行业、平台、商品或投放场景，完整审核必须主动检查某项材料或前置条件 | `proactive_checklist` 核查清单 |
| `workflow_reference` | 流程参考链路 | 规则约束发布前审查、操作流程、履约步骤或内部管理，不适合作为普通文案违规召回 | 流程提醒或人工参考 |
| `platform_access` | 平台或行业准入链路 | 规则约束账户、主体、类目、行业资质、许可证或平台投放资格 | 准入核验或阻断投放 |

### `fact_check` 与 `proactive_check` 的区别

- `fact_check`：文案中已经出现一个需要验证真假的具体宣称。例如“临床试验证明有效”，需要核验临床试验材料。
- `proactive_check`：即使文案本身没有明显违规，也必须按业务场景主动检查。例如保健食品投放前检查广告批准文件。

### 映射角色与审核链路的区别

- 映射角色描述“规则在法律问题判断中起什么作用”；
- 审核链路描述“系统如何处理，需要什么输入”；
- 两者不是同一个字段，也不能互相替代。

例如，一条规则可能是 `direct`，但仍进入 `fact_check`：规则本身可以直接支持某类违规，但个案是否满足规则要件需要外部事实材料。

## 九、人工结论选项

| 选项 | 含义 |
|---|---|
| 保留当前映射 | 当前问题归属正确，无需迁移 |
| 调整问题映射 | 规则保留，但应删除错误问题、迁移到其他现有问题或调整主次 |
| 保留多重映射 | 原文确实分别支持多个问题，不是因关键词相似而重复挂载 |
| 转旁路资产 | 不进入普通文案问题树，转入事实核验、主动核查、流程参考或平台准入链路 |
| 不纳入候选资产 | 与三个赛道及通用广告审核均无关，且没有旁路价值；必须二审 |
| 待讨论 | 现有信息不足，无法作出稳定结论 |

## 十、资产处置选项

| 选项 | 含义 | 与人工结论的区别 |
|---|---|---|
| 保留 | 当前资产可以原样进入后续实验资产 | 表示无需工程改动 |
| 调整映射 | 保留 UID，但修改赛道、问题映射或角色 | 表示需要更新映射资产 |
| 转旁路资产 | 从普通文案召回移出，进入其他处理链路 | 表示需要调整系统接入位置 |
| 不纳入候选资产 | 不进入本轮候选资产，但不删除原始 `jsonbase` | 表示候选层排除，必须二审 |
| 待讨论 | 暂不执行工程动作 | 等待争议裁决 |

“人工结论”表达审核人的业务判断，“资产处置”表达后续需要执行的工程动作。两列相关，但不能混为一列。

## 十一、争议池使用规则

出现以下任一情况，应提交争议池：

1. 原文可能同时支持多个问题，但无法确定主次；
2. 法律规则与平台规则的适用范围存在冲突；
3. 无法区分直接违规、事实核验和主动核查；
4. 规则标题、来源、条款和原文互相矛盾；
5. 现行问题树中没有合适的问题节点；
6. 拟选择“不纳入候选资产”；
7. 一条规则跨多个赛道，现有字段无法准确表达；
8. 原文残缺或来源不明，无法可靠判断；
9. AI 建议进入争议池，人工复核后仍认为存在实质争议。

AI 建议提交争议池不等于必须提交。人工认为问题已经可以根据原文独立解决时，可以改为“否”，并说明理由。

## 十二、审核理由写法

“全部准确”时可以不重复抄写 AI 理由。选择“部分准确”“不准确”或“需讨论”时，建议按以下结构填写：

```text
AI不准确字段：
规则原文适用对象：
核心规制行为：
问题归属修正：
映射角色修正：
审核链路修正：
资产处置修正：
是否需要争议或二审：
```

不要只写“同意”“不同意”“模型错了”。审核理由应让没有参加本轮审核的人也能依据原文复核。

## 十三、完整填写示例

假设规则原文为：“保健食品广告不得涉及疾病预防、治疗功能。”

AI 建议：

```text
AI建议适用赛道：保健食品
AI建议保留问题名称：明示或暗示疾病预防治疗功能或使用医疗用语
AI建议最终映射角色：direct
AI建议最终审核链路：普通文案召回
AI建议资产处置：保留
AI建议提交争议池：否
```

如果人工确认全部正确：

```text
人工复核AI结论：全部准确
审核状态：已完成
二审状态：无需二审
审核日期：2026-09-16
```

其他人工修正字段留空。

如果 AI 错误地建议 `proactive_check`：

```text
人工复核AI结论：部分准确
最终映射角色：direct
最终审核链路：普通文案召回
资产处置：保留
审核理由：原文直接禁止保健食品广告涉及疾病预防治疗功能，仅凭文案即可初步判断，不依赖第三方资质或证明材料，因此应为direct并进入普通文案召回。
审核状态：已完成
二审状态：无需二审
审核日期：2026-09-16
```

## 十四、二审建议

以下规则建议强制二审：

- 拟不纳入候选资产；
- 拟保留多重映射；
- 拟新增问题节点；
- 规则同时跨多个赛道；
- AI 低置信度且人工作出重大调整；
- 法律、行政法规和平台规则存在适用冲突；
- 原文不完整或来源存在疑问；
- 已进入争议池的规则。

其他规则可以按风险抽检。建议优先抽检 `proactive_check`、`supporting_basis` 以及 AI 和人工结论不一致的规则。

## 十六、后续汇总规则

项目负责人汇总时采用以下优先级：

1. 人工修正字段；
2. 人工未修正时继承 AI 建议；
3. 争议池裁决覆盖普通人工结论；
4. 二审最终意见覆盖一审结论。

汇总后应先生成新的候选映射资产，再与原规则库分别运行 A/B 离线测试。只有确认正确规则命中率提高，且误召回率和错误法务路由没有明显反弹后，才考虑接入生产链路。
