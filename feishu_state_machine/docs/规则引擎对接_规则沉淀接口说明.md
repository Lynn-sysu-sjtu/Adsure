# 规则引擎对接 — 规则沉淀衔接接口说明

> 面向规则引擎同学。法务工作台侧已实现轻量规则沉淀，本文说明如何与规则引擎衔接。

---

## 背景

法务工作台每次法务提交「驳回」或「同意有补充」裁决后，纠正内容会自动存成结构化 JSON，下次审核时召回并注入 LLM prompt。

目前注入点在工作台自己的 `call_llm()` 里，不影响规则引擎，**不改动也能跑**。但如果想让规则引擎也能感知这些法务纠正案例，提供两种接入方式：

---

## 方式 A（推荐，改动最小）：在请求体接收 corrections 字段

工作台在 `POST /audit` 请求体里加一个**可选字段** `corrections`，规则引擎读到了就注入 prompt，读不到就忽略（向后兼容）。

### 请求体新增字段

```json
{
  "record_id": "...",
  "industry": "美妆",
  "content": "...",
  "platform": ["抖音"],
  "mode": "标准",
  "corrections": [
    {
      "feedback_type": "override",
      "content_snippet": "买一送一限时特惠，效果媲美医美",
      "ai_risk_level": "高",
      "ai_violation_types": ["绝对化用语"],
      "correct_judgment": "低风险，属于正常促销比较，不构成绝对化用语",
      "reason": "【促销类内容】不违反《广告法》第9条，因为未使用最高级表述，仅为同类横向比较"
    }
  ]
}
```

### 规则引擎侧建议处理逻辑

```python
corrections = request_body.get("corrections", [])
if corrections:
    few_shot_block = "\n【法务历史纠正案例】\n" + "\n".join(
        f"- {c['content_snippet']} → 法务纠正：{c['correct_judgment']}（{c['reason']}）"
        for c in corrections
    )
    # 把 few_shot_block 拼进 system prompt 或 user message 末尾
```

---

## 方式 B（0改动）：不改规则引擎

工作台在收到规则引擎返回结果后，自己再调一次 Claude 做"纠正层"，把 `corrections` 注入那次调用。规则引擎返回结果不变，额外增加一层修正输出再写回飞书。

完全解耦，规则引擎 0 改动。

---

## corrections 数据来源

- 开发环境：`GET http://localhost:5001/api/corrections` 返回全量数据，可直接读
- 正式对接：工作台在调 `/audit` 前会自动把相关 corrections 塞进请求体，**规则引擎不需要主动拉取**

---

## 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `feedback_type` | string | `override`=AI误判被驳回，`refine`=AI遗漏被补充 |
| `content_snippet` | string | 触发纠正的物料片段（前120字） |
| `ai_risk_level` | string | AI当时的原判定风险等级 |
| `ai_violation_types` | list | AI当时推荐的违规类型 |
| `correct_judgment` | string | 法务给出的正确判定 |
| `reason` | string | 法务驳回理由（建议格式：【内容类型】不违反【法规】，因为【理由】） |

---

## 优先级建议

方式 A 效果更好。如果 DDL 来不及，方式 B 也能在 demo 里展示"AI 会从法务反馈中学习"的效果——评委看到的表现是一样的。
