## 阶段一：predictor.py（AI审核核心）⚡ 最高优先级

> 这是整个系统的心脏，其他功能都依赖它输出结果。

- [x] 从多维表格读取物料字段（物料内容、行业领域、各行业专属字段）
- [x] 背景重建：拼接「补充背景资料」+ 行业专属字段，构造完整审核上下文
- [x] 推荐审核模式（极速/标准/深度），默认「标准」，待分配依据后完善
- [ ] 路由判断分配依据（当前由 LLM 自行判断，待团队确认刚性/柔性标准后写入规则）
- [x] 队友规则引擎占位（HTTP API 接口已预留，待队友提供地址后接入）
- [x] LLM 调用：结合命中规则 + 上下文，生成六段式审核报告（DeepSeek，Anthropic 格式中转）
- [x] 回写 ② AI预审段（风险等级 + 命中要点 + 修改建议）
- [x] 回写 ③ AI审核段（审核意见 + 关键实体 + 违规类型 + 风险等级）
- [x] 更新 ⑤流转·当前状态（待运营修改 / 待法务复核）

## 阶段二：运营侧完整卡片流程

> predictor.py 完成后立刻接入。

- [x] 运营点「开启AI审核」→ 上下文重建 → 推送模式确认卡片（极速/标准/深度）
- [x] 运营确认模式 → 正式调用规则引擎 + LLM
- [x] 路由→运营自改：推送「⚠️ AI审核完成」结果卡片（风险等级、命中要点、修改建议、去修改按钮）
- [ ] 「采纳建议，去修改」→ 状态退回「运营起草」，运营改完后重新触发审核（新一轮）
- [ ] 「无需修改，提交法务」按钮（当前运营需手动在工作台操作）

## 阶段三：法务侧通知 + 工作台完善

- [x] 状态变为「待法务复核」时，向「法律与合规」部门所有成员发飞书通知卡片（含风险等级、AI命中要点、工作台链接）
- [x] 部门名称可配置（`config.py` 的 `LEGAL_DEPT_NAME`），不写死
- [ ] 法务工作台正确展示 ② AI预审段 和 ③ AI审核段内容
- [ ] 法务提交裁决后（已有接口），向运营推送结果通知
  - 已通过 → 运营收到「通过」卡片
  - 需修改 → 运营收到「需修改」卡片 + 法务最终意见
- [ ] **多人法务通知去重**：一人完成审核后，其余法务收到的卡片自动更新为「已完成」
  - 方案：发通知时将每条消息的 `message_id` 存入多维表格新字段（`⑤流转·法务通知消息ID`）
  - 法务提交裁决后，批量 `PATCH /im/v1/messages/{message_id}` 将所有卡片改为「✅ 已由 XX 完成审核」
  - 需新增多维表格字段 + 改造 `/api/records/<id>/review` 接口
