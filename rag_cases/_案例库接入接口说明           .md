# 案例库接入接口说明

**审心 · 案例库接入接口说明**



**文档版本**: v1\.0

**日期**: 2026\-07\-17

**对接方**: 队友（案例库）↔ 我方（法务工作台）



---

**1\. 对接方式概述**



\[法务工作台前端\]

↓  选中物料时

\[我方 Flask 后端\]  GET /api/records/\<record\_id\>/cases

↓  转发查询

\[队友案例库 API\]  POST /cases/retrieve

↓  返回相关案例

\[我方前端\] 在物料详情页展示"相关案例"卡片



全程由我方后端代理调用，前端不直连案例库，避免跨域和鉴权问题。



---

**2\. 队友需要提供的接口**



**POST \{CASE\_ENGINE\_URL\}/cases/retrieve**



**请求头**



Content\-Type: application/json

X\-API\-Key: \{CASE\_ENGINE\_API\_KEY\}



**请求体**



\{

"content":  "待审物料文案全文",

"industry": "美妆",

**响应体（失败）**



\{

"code": 1,

"msg": "错误说明"

\}



**超时约定**：我方后端设 timeout=8s，建议案例库检索 ≤5s

返回。超时时我方静默降级，详情页展示"暂无相关案例"，不影响主流程。



---

**3\. 我方新增的接口（供前端调用）**



**GET /api/records/\<record\_id\>/cases**



我方后端收到请求后：

1. 从 Feishu 拉取该记录的 物料内容、行业领域、投放平台

2. 调用队友 /cases/retrieve

3. 将结果原样返回给前端

**响应示例**



\{

"cases": \[\.\.\.\],      // 同上，队友返回的 cases 数组

"record\_id": "xxx"

\}



失败或无匹配时返回 \{"cases": \[\]\} —— 前端处理为空态。

**6\. 联调流程建议**



1. 队友先用 mock 数据跑通接口格式，我方对接 /api/records/\<record\_id\>/cases

2. 用一条真实保健食品物料联调，验证相似案例是否正确召回

3. 确认字段对齐后，我方上线前端展示卡片

---

队友主要需要确认的点：**URL 和 API Key 怎么给我**，以及 similarity

字段你们那边能不能输出。其余字段格式如果有出入直接告诉我，我这边适配成本很低。
