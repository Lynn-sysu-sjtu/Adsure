# 审核违规字段说明

简单说：**你这里的枚举更贴近当前规则库和真实审核逻辑；她那边的枚举更像产品预设的大类清单。**

所以短期联调上，**她需要先补充飞书多选项**，否则你这边返回的真实规则维度会写不进去。

但中长期看，你们应该一起整理一版“统一违规类型 taxonomy”，不要各用各的。

**对比结论**

你这边当前规则库实际会返回：


她那边飞书已有：

```Plain Text

```

她的枚举数量更多，但很多是**未来可能需要的专项标签**，比如：

```Plain Text
概率造假
版号缺失
AIGC未标识
擦边低俗
IP侵权
广告法第九条违禁语
```

这些不一定已经在你当前规则库里被稳定产出。

你这边的枚举虽然少，但更符合当前规则引擎的真实输出，而且有些表达更准确：

```Plain Text
广告可识别性不足
```

比她的：

```Plain Text
广告不可识别
```

更合适，因为很多场景不是完全不可识别，而是标识不充分、种草导流不明显。

```Plain Text
引证内容不规范
```

也比：

```Plain Text
数据引用不规范
```

更宽，因为它可以覆盖专利、荣誉、统计数据、科研结论、认证材料等引用问题。

```Plain Text
平台准入/资质不符
```

也比单独的：

```Plain Text
许可证缺失
版号缺失
```

更适合作为上位类。

**我建议这样处理**

短期 MVP：

让她把你这 6 个缺失项补进飞书多选字段：

```Plain Text
价格促销误导
平台准入/资质不符
广告代言不合规
广告可识别性不足
引证内容不规范
用户评价/种草误导
```

这样你当前规则引擎的返回就不会写回失败。

中期整理：

保留她那边已有的细分类，但建立映射关系。例如：

```Plain Text
平台准入/资质不符
  可下挂：许可证缺失 / 版号缺失 / 备案资质不符

引证内容不规范
  可下挂：数据引用不规范 / 荣誉证明不实 / 认证材料不实

广告可识别性不足
  可下挂：广告未标识 / 种草软文未披露 / 排名测评导购未标识

虚假宣传
  可下挂：虚假广告 / 功效不实 / 价格活动不实 / 销量荣誉不实
```

所以不是你完全补她，也不是她完全补你。

更准确的分工是：

```Plain Text
短期：她补飞书选项，保证能接收你当前规则库真实输出。
中期：你们一起统一违规类型层级，把“规则维度”和“产品展示枚举”拆开。
```

我不建议你现在为了适配她的飞书选项，把本地规则库里的 `dimension` 全部改成她那版。因为那会损失你们已经整理好的法律判断颗粒度。
